# Единый матч: дизайн

Статус: согласовано владельцем с поправками ниже.

## Поправки владельца (важнее всего остального текста)

- Матч и партии — общие сущности, создаются глобально. Статистика внутри них бывает трёх видов. Режимы не создают матчи.
- Названия режимов: **Студия PRO** (3D), **Ручной PRO** (компьютер, кнопки без 3D), **Экспресс stat** (пульт с телефона, минималистичный). Внутренние ключи: `studio`, `manual`, `express`. В тексте ниже «3D» — Студия PRO, «Кнопки» — Ручной PRO, «Пульт» — Экспресс stat; `buttons`→`manual`, `remote`→`express`.
- Пульт — небольшая дополнительная функция, дорабатывать не надо. В настройках раздел с адресом пульта, с телефона выбираем любой матч, нажимаем кнопки, всё пишется на компьютер. Статистику смотрим только на ноутбуке. Пульт консервативный и простой.
- Аналитика — новое меню с логичными фильтрами: всё сразу или конкретный матч, плюс выбор режима. Режим без данных не подсвечен.
- Боковое меню как в Notion: сворачивается кнопкой, в свёрнутом виде открывается по наведению на левый край. Аналитика открывается в основной области, как остальные разделы, в том же стиле. Под пунктом «Аналитика» — постоянный список переходов (Обзор, Ход партии, Тепловые карты и т. д.).

## Зачем

Сейчас «Волей Метрика» — три программы под одной обложкой: студия, детальный пульт и быстрая статистика. У каждой свой список матчей, своё создание матча, свои настройки и свой дашборд. Владелец нажимает на одно, а открывается другое.

Нужна одна программа. Компьютер — основа, телефон только пульт. Главная сущность — матч. Основной сценарий: после игры смотреть видео и собирать статистику в 3D.

## Что владелец сказал прямо

- Компьютер — основа: всё создаётся и настраивается на нём. Телефон без компьютера не работает.
- Есть одна сущность — матч. Его можно открыть в трёх вариантах, и у него три отдельных вида статистики.
- Статистика не суммируется. На дашборде матча вид выбирается вкладкой; вкладка вида, которого нет, серая.
- 3D начинается с чистого листа, данные пульта в него не подтягиваются: достраивать 3D поверх пульта бессмысленно.
- Пульт используется редко и собирает абсолютно минималистичную статистику, без точек. Она должна работать идеально.
- На дашборде нужна красивая мини-карточка матча: эмблемы, счёт по партиям, счёт каждой партии, прочерки там, где счёта нет.
- Видно, сколько партий собрано. По нажатию на матч под ним появляются партии.
- Партии идут строго по порядку: третью нельзя собирать, пропустив вторую.
- Настройки и команда не должны уводить в студию.
- Номера на спинах есть у всех игроков всегда.
- Плашки над игроками меньше и прозрачнее, с первыми тремя буквами имени. Переключатель номер/имя работает честно.

## Цели

1. Один список матчей и одно место создания матча.
2. Три независимых вида статистики внутри одного матча.
3. Одна карточка матча на главной и на дашборде.
4. Настройки открываются там, где нажали, без перехода на другой экран.
5. Любая кнопка делает то, что на ней написано. Тупиков и лишних экранов нет.

## Не цели

- Новые показатели и новые блоки статистики.
- Суммирование видов статистики.
- Перенос событий из одного вида в другой.
- Работа телефона без компьютера.

## Провал, даже если всё технически работает

- Потеря или искажение существующих матчей при переходе на новый формат.
- Экран, на который можно попасть и нельзя понятно выйти.
- Кнопка, ведущая не туда, куда обещает подпись.

## Три вида статистики

| Вид | Название в интерфейсе | Экран | Что в нём | Движок |
|---|---|---|---|---|
| `studio` | 3D | `studio.html` | каждое касание, точки, видео | `replay` |
| `buttons` | Кнопки | `detailed.html` | каждое касание кнопками, без точек | `replay` |
| `remote` | Пульт | `quick.html` | кто закончил розыгрыш и чем | `replayQuick` |

Моё решение: соответствие именно такое. Владелец описал три режима: 3D, упрощённый без 3D и минималистичный через телефон или компьютер. Так они ложатся на существующие экраны.

## Данные

Матч остаётся одним файлом `match-<id>.json`. Общие поля: соперник, дата, турнир, формат, состав, пресет, схема, роли, скаутинг, видео.

События лежат раздельно:

```json
{ "id": "…", "opponentId": "…", "stats": { "studio": { "events": [] }, "buttons": { "events": [] }, "remote": { "events": [] } } }
```

Движки не меняются: им передаётся матч с подставленным `events` нужного вида.

API событий получает параметр вида: `/api/matches/:id/events?src=studio`. Сводка в списке матчей отдаёт по каждому виду партии со счётом, количество событий и признак окончания.

### Перенос старых матчей

При запуске сервера, один раз:

1. Сделать резервную копию (`makeBackup`).
2. `mode: 'quick'` → `stats.remote`.
3. Остальные матчи: если хотя бы у одного события есть `to`, `from` или `vt` → `stats.studio`; иначе → `stats.buttons`.
4. Поле `mode` и верхний `events` убрать.

Автоматически матчи не объединяются: две игры с «Татарлар» имеют разные даты, это могут быть разные матчи.

Уточнения (мои решения):

- Матч со смешанными событиями целиком уходит в `stats.studio`: вид не делится по событиям.
- У матча без событий все три вида пусты.
- Отметки времени видео (`vt`) есть только у событий 3D. Список видео общий для матча, но его использует только 3D.
- Опция скаутинга общая для матча, номера соперника хранятся в событиях своего вида.
- Запись событий идёт через существующую очередь сервера `serial()`, поэтому телефон и компьютер могут писать одновременно. Виды лежат в разных списках и друг другу не мешают.
- Старая копия и старый ZIP переводятся в новый формат при загрузке. Импорт матча с уже занятым `id` остаётся как сейчас: матч получает новый `id`, слияния нет.

Перенос обязан учесть все места, где читается `events` или `mode`: экспорт и импорт (`transfer.js`), резервные копии и восстановление старых копий, корзину, CSV, `scripts/demo.js`, `offline.js`, `player.js`.

## Партии

- В каждом виде партии идут по порядку. Следующую можно начать только после окончания предыдущей в этом же виде. Движок это уже соблюдает, интерфейс должен показывать это явно.
- Количество партий в карточке определяется форматом матча: до 2 побед — три ячейки, до 3 побед — пять, одна партия — одна.
- Партия заканчивается сама по счёту, как сейчас и в `replay`, и в `replayQuick`. Отмена последнего очка снова открывает партию; правка сыгранной партии пересчитывает всё.
- Если матч решён раньше (2:0 при формате до 2 побед), оставшиеся ячейки — прочерки без кнопки «Начать».

## Карточка матча

Один компонент `match-card.js` для главной и дашборда. На карточке:

- эмблемы и названия команд, дата, турнир;
- счёт матча по партиям крупно;
- счёт каждой партии ячейками: `25:15 · 14:25 · —`; идущая партия отмечена, несыгранная — прочерк;
- три значка видов: 3D, Кнопки, Пульт. Вид без данных серый.

Моё решение: на закрытой карточке счёт берётся из вида, где сыграно больше очков; при равенстве приоритет 3D, Кнопки, Пульт. Значок этого вида выделен.

### Раскрытие

Нажатие на карточку раскрывает под ней таблицу: строки — виды, столбцы — партии.

```
          Партия 1   Партия 2   Партия 3
3D         25:15      14:25     ▶ Начать
Кнопки     —          —         —
Пульт     ▶ Начать    —         —
```

- Сыгранная партия: нажатие открывает дашборд этого вида на этой партии.
- Идущая партия: нажатие продолжает ввод.
- Следующая по порядку: кнопка «Начать».
- Остальные: прочерк, нажать нельзя.
- В конце строки: «Открыть» (экран ввода этого вида) и «Дашборд».

Моё решение: таблица, потому что она сразу отвечает на вопрос «что собрано» по всем видам и показывает порядок партий.

## Главная

- Боковое меню: Главная, Матчи, Команда, Аналитика, Телефон, Настройки. Отдельного «Дашборд быстрой» нет.
- «Новый матч» — окно поверх главной: соперник, формат, турнир. После создания раскрывается карточка нового матча; вид выбирается там.
- «Продолжить» открывает последний экран ввода с его видом. Это запоминается в браузере; если матча уже нет, берётся самый свежий матч.

## Настройки

Настройки, команда, расстановки, зоны доводки, данные выносятся из `studio.js` в отдельный модуль, который подключают и главная, и студия. Окно открывается поверх того экрана, где нажали. Настройки пульта (`detailed.html#settings`) убираются, QR остаётся в разделе «Телефон».

Адреса `studio.html#settings` и `studio.html#new` больше не используются.

## Экраны ввода

`studio.html`, `detailed.html`, `quick.html` открываются только с матчем (`#m=<id>`). Создания матча, настроек и своего меню в них нет. Сверху у всех одна кнопка «Главная» (на телефоне — «Матчи»).

Без `#m` на компьютере экран переходит на главную.

## Телефон

QR ведёт на список идущих и недавних матчей. Создавать матч и менять настройки там нельзя. Моё решение: с телефона доступен только вид «Пульт»; владелец сказал, что пульт на телефоне собирает минималистичную статистику. Вид «Кнопки» открывается на компьютере, его экран при этом не меняется.

Начинать партии вида «Пульт» на телефоне можно: это ввод, а не настройка. Ограничение только в интерфейсе, проверки устройства на сервере нет.

Если матчей нет, телефон показывает «Создайте матч на компьютере». Очередь без связи (`offline.js`) сохраняется.

## Дашборд

Один вход: `stats.html#m=<id>&src=<вид>`.

- Сверху карточка матча, под ней вкладки 3D, Кнопки, Пульт (пустая серая и не нажимается), под ними вкладки партий.
- Открывается вкладка вида, показанного на карточке.
- 3D показывает всё, что есть сейчас.
- Кнопки — те же блоки, но без тепловых карт и блоков с точками.
- Пульт — блоки быстрого дашборда с его настройкой блоков.
- Без выбранного матча, по всем матчам: сначала выбирается вид, статистика считается только внутри него, по всем матчам с данными этого вида, включая неоконченные. Текущие фильтры (соперник, турнир) сохраняются.

Отдельная страница `quick-stats.html` как вход исчезает. Строитель решает, встроить её блоки в `stats.html` или оставить внутренней страницей с той же шапкой; для пользователя это один дашборд.

## 3D: номера и подписи

- Номер на спине и груди есть у всех игроков всегда. `0` — настоящий номер, он показывается и не считается пустым (возврат моей ошибочной правки, в том числе `Number(p.num) || ''` в `app.js`).
- Моё решение: если поле номера действительно пустое, на спине порядковый номер в составе.
- Режимы подписи: номер, три буквы имени, номер и три буквы, без подписи. Каждый режим показывает ровно то, что заявлено, без подмен.
- Плашка меньше и полупрозрачная; размер почти не зависит от близости к камере.

## Проверка

Перед сдачей проходится вся карта сценариев по экранам со скриншотами на 1366×768 и 390×844, на копии данных:

- каждая кнопка главной, карточки и дашборда: подпись совпадает с результатом;
- новый матч, вид, партии по порядку, конец матча, возврат;
- запрет пропуска партии;
- перенос: копии реальных данных и демо-данных, сверка количества событий и счёта до и после;
- экспорт, импорт, резервная копия, корзина;
- пульт без связи и досылка;
- все режимы подписи в 3D, номера на спинах.

Автотесты в `test/`: перенос, сводка по видам, правила партий, API `?src=`.
